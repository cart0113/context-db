# Keep context-db Small

Every note in the knowledge base has to be read by later agents and kept true
as the project changes. Leaving it smaller is as good a result as leaving it
larger.

- Write the least that does the job: the fact, the rule, the pitfall, and the
  reason when the reason is the point. No background, and no account of how
  you found it.
- One fact, one place. Change the note that already covers a topic; do not
  start another.
- Replace, do not append. Rewrite the lines that are now wrong, and add no
  "update" paragraph or history. Git keeps what was there before.
- Delete what is no longer needed: what has become false, what the project now
  says itself, what was about work that is finished or code that is gone.
- When it is not obvious how much to clean up, ask the user how far to go. Do
  not keep a note just in case, and do not delete one without saying so.
