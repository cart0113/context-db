# Commit

Commit every file touched in this session: code, docs, configuration,
`{cdb}/`, everything. The scope is the whole session, not only the context-db
update. If `git status` shows changes you did not make, ask before including
them.

Before writing the message, check the bundles under `{cdb}/` for commit-message
standards and follow them if any exist. Otherwise say what was learned and why
it matters: corrections, pitfalls, decisions, new conventions. The bar is lower
than for context-db entries, so capture session learning freely. When there is
nothing notable, a simple message is fine.
