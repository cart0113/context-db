# Context-db Audit

The user wants to see what you read, for the instruction, from the folders
that `/context-db prompt` listed, and by what path, so that they can make the
knowledge base better. You were not told what the report holds before you
read, so that it could not change what you read. Read nothing more for it.

Show the user this report now, under the heading `Context-db audit`. Work from
the commands you ran, so that no step in those folders is left out: a file
that turned out not to matter is what they most need to see.

- The trail, numbered in the order you went: each folder you listed, each
  file you opened or searched in one, and each file or web page that one of
  those sent you to. Leave out the skill's own files, the settings, and
  whatever else you read in the project that no note sent you to. For each
  step, give its path, what led you to it (a section of what
  `/context-db prompt` printed, a description in a listing, or a link in a
  file), and what you took from it, or that it did not bear on the
  instruction.
- What came from outside this project: the steps in a background folder or a
  Global Context folder, and any web page or file in another repository. Say
  so if there were none.
- What you looked for and did not find, and any description that misled you
  or left you unsure whether to open what it describes.

Then carry out the instruction, without waiting for a reply.

When you have finished it, end your reply with a second part, under the
heading `Context-db audit, after the work`:

- Any further steps in those folders, in the same form.
- Which files the work rested on in the end, and which it did not need.
- What you had to guess, or ask the user, because no note said it and the
  project's assets do not show it, and any note that the project's assets
  contradicted.
