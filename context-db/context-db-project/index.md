# Subfolders

* [context-db-migrate-from-v0.0](context-db-migrate-from-v0.0/index.md) - Step-by-step guide for an agent migrating a project's context-db from v0.0 to v0.1 (OKF format) — install the new skill, run the migration script, configure, fix lint, and handle shared bundles, ON files, and wip. Includes the full list of what changed.
* [context-db-theory](context-db-theory/index.md) - Information retrieval theory behind context-db — why hierarchy works, cross-references, what we rejected, and the fundamental context delivery problem (attention dilution, obedience poisoning, memory corruption)
* [design-decisions](design-decisions/index.md) - Design decisions and their reasons — OKF adoption, static index files, link form and symlink rules, which frontmatter keys exist, folder descriptor naming, config layering, gate-before-action prompt ordering, Python and argparse.
* [wip](wip/index.md) - Current work in progress — plans and research for what is being built right now (the v0.1 ground-up rewrite). Read first when picking up work; files here are deleted once the work lands.
* [writing-docs](writing-docs/index.md) - Conventions for writing this project's documentation — the Sphinx docs site, the README, and which pages include agent-facing text verbatim.

# Files

* [Background bundles](background-bundles.md) - How background bundles get mounted under context-db/ (committed copy, private symlink, submodule, git-sync) and the rules that keep them safe — top-level only, read-only, self-contained links, indexes generated by the owning repo. Also called cross-project sharing.
* [Context Engineering Research Landscape (2024–2026)](context-engineering-research.md) - Research landscape on context engineering for LLM coding agents — how tools handle context, structured vs unstructured evidence, and implications for context-db
* [Lessons Learned](lessons-learned.md) - Prompt-writing lessons from building context delivery — late-session recall, why not to pre-load, rules last and instruction last, positive framing first, cwd-relative paths, and retiring specialized primitives. Read before editing anything under skill/context-db/prompts/.
* [context-db (project notes)](overview.md) - Orientation for agents modifying the context-db codebase — where the skill lives, what is generated, what to run after a change. Not an explanation of what context-db is; the README covers that.
* [context-db Project Coding Standards](project-coding-standards.md) - context-db-specific coding standards — overrides and additions to general-coding-standards. No shims, no defensive .get(), triple-quote editable text blocks, "project assets" framing.
