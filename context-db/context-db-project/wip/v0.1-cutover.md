# v0.1 cutover

The rewrite is built on the `v0.1` branch: one script, four commands, OKF
bundles, Sphinx docs, tests. What remains needs the repository owner or real
use.

## Owner-only steps

1. In the repository's Pages settings, switch the source from "Deploy from a
   branch" to "GitHub Actions". Until then the deploy job in
   `.github/workflows/docs.yml` fails while the build job passes.
2. Make `v0.1` the default branch.
3. Update the repository description and homepage link.

## Migrate the real projects

Follow
[the migration guide](../context-db-migrate-from-v0.0/context-db-migrate-from-v0.0.md)
in each work project and in the shared standards repository. The
`writing-effective-skills` bundle this repo mounts is still in v0.0 format.

## Questions for real use to answer

- Is listing `wip/` on every `prompt` worth its tokens?
- Does anyone miss `maintain`? The replacement is
  `update "audit <folder> and cut"`.
- Is `context-db-on-markdown` the right folder name? It is one constant,
  `ON_DIR_NAME`, in the script.
- Does the agent reliably read the interpreter from the config, or does the
  skill need a launcher?
- OKF v0.3 is being developed in a neutral `open-knowledge-format` GitHub org
  that was not public as of 2026-11-10. Re-check the spec when it appears; see
  [okf-adoption.md](../design-decisions/okf-adoption.md).
