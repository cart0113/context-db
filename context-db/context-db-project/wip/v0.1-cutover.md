# v0.1 cutover

## Goal

Every project that used context-db v0.0 runs on v0.1, and the open questions
below are settled by using it for real work.

## Where it stands

The rewrite has landed: `v0.1` is the default branch, CI runs on Python 3.8 and
3.13, and the docs site deploys from it. The instructions were tested by handing
them cold to three fresh agents (first-time setup, a full prompt/update/wip
session, and a migration of a copy of the v0.0 tree). All three finished, and
what they tripped on is fixed. None of that was a real project.

## Next

1. Migrate one real work project with
   [the migration guide](../context-db-migrate-from-v0.0/context-db-migrate-from-v0.0.md).
   It is the first true test of the guide. Watch for a long "Mentions of v0.0
   machinery" list, wrong type guesses, and anything the guide leaves to
   judgment. Fix the guide as you go.
2. Migrate the shared standards repository in its own checkout. It owns
   `context-db/writing-effective-skills`, which this repository mounts and
   which is still in v0.0 format. Until then `prompt` falls back to listing
   that folder.
3. Migrate the remaining projects.

## Needs the owner

- A `LICENSE` file. The README says MIT, but the repository has no license text.
- The GitHub repository description and website link.
- `hooks/pre-commit` is not installed in this clone. Install it with
  `cp hooks/pre-commit .git/hooks/pre-commit`.

## Undecided, for real use to answer

- Is listing `wip/` on every `prompt` worth its tokens?
- Does anyone miss `maintain`? The replacement is
  `update "audit <folder> and cut"`.
- Is `context-db-on-markdown` the right folder name? It is one constant,
  `ON_DIR_NAME`, in the script.
- Does the agent reliably read the interpreter from the config, or does the
  skill need a launcher?
